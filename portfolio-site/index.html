A LITTLE ABOUT MY WORK

Useful tools start with a real support problem.

My focus is the space between a technical signal and a useful next step. These examples turn device checks and exported service data into reports a technician can review.

The projects use PowerShell, Windows built-ins, Microsoft Graph, and normalized CSV exports. They are designed to be easy to inspect and adapt.

The examples are deliberately read-only: they report findings and leave the operational decision with the technician.

AUTOMATION IN THE REPOSITORY

Five workflows that keep the tools ready to use.

GitHub Actions checks code changes, publishes this site, and packages tagged releases.

01SCRIPT CHANGES

PowerShell static analysis

Runs PSScriptAnalyzer on pull requests and main-branch changes. Analyzer errors are shown in the Actions run so issues can be fixed before the scripts are used.

View workflow↗
02SCRIPT CHANGES

PowerShell compatibility

Parses the repository’s PowerShell files with Windows PowerShell 5.1 and PowerShell 7 on Windows to catch syntax differences early.

View workflow↗
03SITE CHANGES

Portfolio quality checks

On portfolio changes, checks JavaScript syntax and confirms local files and in-page links resolve, so missing assets and broken sections appear in the Actions run.

View workflow↗
04MAIN OR MANUAL

GitHub Pages deployment

Publishes the portfolio-site folder when it changes on main, or when manually started from the Actions tab.

View workflow↗
05VERSION TAG

Tagged release packaging

When a version tag such as v1.0.0 is pushed, creates a ZIP of the source and a SHA-256 checksum as a downloadable Actions artifact.

View workflow↗
